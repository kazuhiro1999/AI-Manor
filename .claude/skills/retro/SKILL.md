# /retro — 執事の自己改善サイクル

**観測して終わりにしない。必ずファイルを1つ以上変更する。** 変更のない retro は失敗。

## 手順

1. **観測**（`butler/GROWTH.md` の「観測の視点」5項目を自問する）
   - 主人を待った瞬間はどこか
   - 同じ説明を2回以上したか
   - 探すのに手間取った情報はどれか
   - 主人に訂正されたことは何か
   - やらなくてよかった作業はどれか

   直近の `home/LOG.md` と会話履歴を根拠にする。**憶測で書かない**

2. **仮説** — 「なぜそれが起きたか」を仕組みの言葉で1文にする
   （「気をつける」は仮説ではない。気をつけなくても起きない形にする）

3. **打ち手** — 次のいずれかを**実際に編集する**（L2）

   | 症状 | 変える場所 |
   |---|---|
   | 起動時の振る舞いがぶれる | `CLAUDE.md` |
   | 判断基準がぶれる／同じ確認を繰り返す | `butler/POLICY.md`（数値なら `butler/policy.toml`） |
   | 手順が毎回ゼロから | `.claude/skills/` に新スキル |
   | 許可プロンプトで止まる | `.claude/settings.json` の allow |
   | 部下との同期がずれる | `butler/AGENTS.md` |
   | 口調・報告の質 | `butler/SOUL.md` |
   | 方向性そのもの | `butler/INTENT.md`（主人の裁定が要る → `manor decision ask`） |

4. **記録** — `butler/GROWTH.md` に1行追記（観測／仮説／打った手／**検証方法**）
   検証方法は「次セッションで何を見れば成功と分かるか」を具体的に書く

5. **前サイクルの検証** — `butler/GROWTH.md` の未検証行を確認し、効いていなければ打ち手を差し替える

## 制約

- HG固定領域（認証・課金・個人情報・外部送信・不可逆削除）の緩和は執事が行えない。
  `manor decision ask` へ提案として積む
- 打ち手は1回につき1〜2個まで。まとめて変えると何が効いたか分からなくなる
