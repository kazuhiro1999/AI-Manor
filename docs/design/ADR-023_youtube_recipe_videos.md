# ADR-023: YouTube のレシピ動画（探す・取り込む）

- 状態: **採択・実装済み**（2026-09-25。D1〜D6 は主人の裁定。当たり率の実測だけ残る）
- 関係: ADR-009（拡張）、ADR-014 D5（利用者ごとの設定）、ADR-015（レシピ帳の取り込み）、ADR-016（動画リスト）
- 検証の道具: 拡張 `youtube`・`manor chef youtube probe`（`staff/chef/youtube.py`）

## 1. 何をしたいか

主人と同居予定の方は、YouTube で見たレシピを再生リストに保存し、料理のときに見返す。
① 「豚肉」「チャーハン」のような**素材・料理名で**保存した動画を探したい。
② 概要欄やコメントに書かれたレシピを**レシピとして取り込み**、動画へのリンクを添えたい。
YouTube Data API v3 を拡張として足し、利用者ごとの API キーで読む（まず主人のキーで検証）。

## 2. 検証で分かったこと（2026-09-25。共有いただいたショート1本・再生リスト1つ）

- API キーで再生リスト・動画・上位コメントが読める。割り当ては 1 本あたり 2 単位（`videos`＋`commentThreads`）、
  再生リストは＋2（1 日 10,000 単位）。**非公開の再生リスト・「後で見る」は API キーでは読めない**（OAuth が要る）。
- **ショートは概要欄が空**で、レシピは**投稿者本人のコメント**（関連順 1 位）に全文あった。題名の行「★…」、
  「・名前（量）」、【A】の札、「A・B（量）」、《作り方》①②… の書き方。規則で材料 11 行・手順 3 つを読めた
  （括弧の中の量・丸数字・続きの行は実物で見つけて直した）。
- 読めた下書きは既存の流れにそのまま乗る: 栄養の推定（名寄せ 85%、残りは ADR-022 の自動調べの対象）、
  塩もみの補正（「塩ずり→洗い流す」。ADR-019 §6）。
- 画面の文字・音声にしか無いレシピは Data API では取れない（字幕の取得は動画の持ち主の許可が要る）。

## 3. 規約（YouTube API Services Developer Policies）

- **III.E.4**: API で得たデータ（題名・概要欄・コメント等）は**最長 30 日**まで。
- **III.E.4.h**: API データから新しいデータ・指標を作ってはならない。
  → ①の検索用の情報は「30 日で消える一時的な控え」にする。②は「読んだものを下書きとして見せ、確かめて
  登録するのは使う人」とし、manor が自動でレシピを作り溜めることはしない。

## 4. 決めたこと

### D1 ①検索用の情報は 30 日の控え（主人の裁定）
再生リストの同期で題名・タグ・ハッシュタグ・読めた材料名を控え、同期のたびに取り直す。**30 日取り直せなかった
ものは消す。** 探すのは manor の手元（YouTube の `search.list`＝100 単位は使わない）。**置き場は未決**（§6）。

### D2 ②読める場合は下書きを出し、確認・修正・登録は使う人に任せる（主人の裁定。実装済み）
- 取り込み画面（`POST /kitchen/recipes/import`）に YouTube の動画の URL を貼ると、概要欄と上位コメントから
  読んだ材料・作り方で下書きを返す。**保存しない。** 見ている利用者の API キー（無ければ principal）。
- 一番材料が多く読めたところを採る。同じ数なら 概要欄 → 投稿者のコメント → 他人のコメント。
  どこから読んだかを注記に出す（「投稿者のコメントから読みました。動画と見比べて確かめてください」）。
- 題名は読み取り元の「★…」の行、無ければ動画の題名（ハッシュタグ・絵文字を落とす）。出典は動画の URL、
  写真はサムネイル（直リンク）。手順が無ければ「動画を見ながら作る」の1手順。材料が読めなくても下書きは返す。

### D3 同じ出典は2度登録しない（実装済み。サイトの取り込みにも効く）
- 突き合わせの鍵（`recipes.source_key`）: YouTube は**動画 ID**（`youtu.be/…?si=`・`watch?v=`・`shorts/` を
  同じとみなす）。それ以外は scheme・host の大小・末尾 `/`・`#`・共有の印のクエリ（`utm_*`・`si` 等）を無視し、
  ページを決めるクエリは残す。
- `recipes.add`／`update` が同じ鍵の（畳んでいない）レシピを見つけたら断る（web は 409）。取り込みの下書きは
  `duplicate` を添え、画面は「このレシピはもうレシピ帳にあります（開く）」を出す。出典の無い手入力は何本でも入る。

### D4 分類の手がかりから調味料を外す（検証で見つけた既存の穴）
「鶏がらスープの素」で 汁物・肉 に化けていた。基礎調味料（`[basics]`）は種類・主な材料の手がかりにしない。
ジャンルには効かせる（「和風だし」→和食）。

## 5. 範囲外（今は）
- 非公開の再生リストを読むための OAuth。
- 画面の文字・音声からレシピを読むこと。

### D5 ①はレシピ帳に混ぜる（主人の裁定。実装済み）
主人「作るときはリンクを押して YouTube に移ればよい（工程ごとの図は用意できない）。レシピ帳に検索や絞り込みは
あるので、そこに YouTube 経由のレシピも足す」。動画リスト（ADR-016。XR がながら見する音楽）には混ぜない
——XR の再生の一覧が汚れ、持ち方（手で足してずっと残す／同期で取り直し 30 日で消える）も違う。
- 表 `chef_video`（動画 ID で1行＝家族で重複しない）・`chef_video_source`（誰のどの再生リストか。同じ動画が
  2人の再生リストにあれば2行）・`chef_video_sync`（再生リストごとの最後の同期）。
- 同期（`youtube.sync`）: 全員の再生リストを読み、動画の中身は1回だけ読む。再生リストから外れたものは消す。
  **読めなかった再生リストの控えは消さない**（一時的な失敗で家族の動画が消えないように）。`fetched_at` が
  30 日より古いものは消す。一覧（`GET /kitchen/videos`）を開いたとき前の同期から 12 時間（`[youtube].sync_hours`）
  以上たっていれば背景で同期。手動の「再生リストを同期」と `manor chef youtube sync` も。
- 一覧: レシピ帳の検索語・分類3軸で絞り、カードに「▶ YouTube」の印。押すと YouTube を新しいタブで開く。
  「主人の『レシピ』」のように出どころを添え、読めるものは「下書きにする」。**取り込み済みの動画は出さない**
  （取り込んだレシピが並ぶ）。タグ・お気に入りで絞っているときは動画を出さない。題名はハッシュタグ・絵文字を落として表示。
- 分類は題名・ハッシュタグ・読めた材料から推定（D4 と同じ規則）。

### D6 家族の動画は共有する（主人の裁定）
「レシピはプライバシー関係なく共有したほうがいい」。台所は共通（ADR-014 D4）なので、誰が開いても家族全員の
再生リストの動画が並ぶ。データは動画 ID で1行にまとめ、どの再生リストからかは残す。再生リストが公開・限定公開
なら、その人のキーが無くても主人のキーで読む。

### D7 検索の当て方（レシピ帳と動画で同じ）
空白で区切った語は全部に当たるものに絞る。言い換え（`lexicon.toml` の `[search].synonyms`: 豚肉＝豚バラ・豚こま、
チャーハン＝炒飯、醤油＝しょうゆ…）とカタカナ・ひらがなの違いを吸収する。レシピ帳の既存の検索にも同じ当て方が
効くようになった（`recipes.match_query`）。動画は「題名 → 材料 → ハッシュタグ」の順で並べ、当たった理由を添える。

## 6. 残り
- 当たり率: 同居予定の方の再生リストに 10〜20 本入れて `manor chef youtube probe` で測る（概要欄とコメントの
  どちらにレシピがあるか。読めないものは「レシピ帳に入れる（材料は手で）」になる）。
