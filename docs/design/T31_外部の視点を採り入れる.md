## 0. 初版で外していたこと（先に書く）

初版で執事は「**重複検知が本丸**」「**記事は消してよい**」「**直近N件だけ見て古いものはアーカイブ**」
と書きました。**3つとも一次情報に反していました。**

| 初版 | 調査が示したもの |
|---|---|
| 重複検知が本丸 | **効果検証が本丸。** 順位は 効果検証 → 重複 → 肥大化 |
| 記事そのものは残さない | **2層（生の記録＋判断）が標準。** 1層に畳むと崩壊が実測されている |
| 直近N件だけ見てアーカイブ | **それは FIFO。捨て方として最悪**（捨てないより悪い） |

**根拠は §1〜§3。** 初版のまま走らせなくてよかった、というのが正直なところです。

## 1. 本丸は効果検証（初版の訂正）

**PDSA サイクルを回した120プロジェクトの調査**:

- **98% が「改善した」と報告した**
- **事前に設定した目標を達成したのは 27%**
- **手法の鍵を全部適用していたのは 4%**

「効いた気がする」は、ほぼ当てになりません。そして**効果を測っていないと、
捨てる順位が付けられません**——何が効いたか分からないものを、どうやって選んで捨てるのか。

だから効果検証が先です。**肥大化は単独ではほとんど害を出しません**（後述）。

### だから: 採るときに「何が起きれば効いたと言えるか」を必ず書く

`00_butler/GROWTH.md` は既に **観測 → 仮説 → 打った手 → 検証** の4列です。
外から採ったものも同じ列に入れます。**ただし1つ足します**:

> **採用した時点で「いつまでに、何が観測できれば効いたと言えるか」を書く。**
> 書けないなら、それは**採らない**。

これが PDSA の 27%／4% への答えです。**後から「効いた気がする」と書けなくします。**

## 2. 記事は消さない（初版の訂正）

初版は「記事そのもの・要約は残さない」と書きました。**危険でした。**

**1層に畳む設計は、実測で崩壊しています**（ACE の context collapse）:

```
1ステップで 18,282 → 122 トークンに要約
精度 66.7 → 57.1（文脈なしの 63.7 より低い）
```

**要約し直すたびに、何が失われたか分からなくなる。** そして失われたことに気づけません。

→ **2層にします。**

| 層 | 何 | 消すか |
|---|---|---|
| **素材** | 拾った記事の出どころ・日付・1〜3文の視点 | **消さない。期限も切らない** |
| **判断** | 採った／採らなかった、その理由、効果の宣言 | **消さない** |

**期限を切らないのは根拠があります。** 調査で見つかった15の運用のうち、
**年数で切っているのは「合成物」（レビュー・ガイドライン）だけ**で、
**素材（ノート・決定・仕様）に年数を切った例は皆無**でした。

## 3. FIFO で捨てない（初版の訂正）

初版の「直近◯件だけを見て、古いものはアーカイブ」は **FIFO そのもの**です。

```
FIFO で捨てた場合   Precision@5 = 3.8%
捨てなかった場合    Precision@5 = 12.4%
賢く捨てた場合      Precision@5 = 15.8%
```

**古い順に捨てるのは、捨てないより悪い。** 主人の懸念（30日で30個）への答えは
「古いものを畳む」ではありません。**そもそも素材は1行なので、増えても困りません。**

困るのは**取り出せなくなること**で、それは量ではなく**構造**の問題です（次節）。

## 4. 重複は「探して気づく」のではなく「同じ枠に足す」

初版は「毎晩 grep して当たったら既適用に倒す」と書きました。
調査では、**「検索して気づく」形はほぼ存在しません**でした。標準は:

| 例 | やり方 |
|---|---|
| ACE | bullet に**一意IDと helpful/harmful のカウンタ**。埋め込みで既存に併合 |
| ExpeL | 既存を**書き換えて +1**（新規に足さない） |
| ADR | `superseded by` で**新→旧を明示リンク** |
| PRISMA 16b | 落とした理由を残し、**再評価を防ぐ** |

→ **同じ視点が2度来たら、行を足さずに既存へ「+1」と日付を書き足す。**

**2度来た＝重要である証拠**でもあります。カウンタは重複の抑制と、
「何が繰り返し言われているか」の測定を兼ねます。

## 5. 止まったことに、当人は気づかない

**この設計で一番怖いのはここです。**

Cochrane の「生きたレビュー」25本の追跡:

- **13本（52%）が一度も更新されなかった**
- 7本が1年以上未更新、**119件の新しい研究を取りこぼした**
- **にもかかわらず、著者たちは「結論はまだ現行だ」と感じていた**

執事は 2026-08-27 に**まったく同じ形**を踏んでいます（[[00_butler/GROWTH]] G42:
見張りが1日半止まっていたのに、ログは毎行 INFO で成功を名乗っていた）。

→ **外から見張ります。** `butler-board --check` に検査を1つ足す:

> **`GROWTH.md` に外部由来の採用が N 日間1件も無いのに、
> 台帳（素材）だけが増えている** → 「読んでいるが採っていない」

**読むのをやめたことにも、読むだけになったことにも、機械が気づく形にします。**

## 6. この設計の生存率について（正直に）

調査は**厳しい事実**も出しています。

> **ADR（判断を記録する実践）はリポジトリの約半数が1〜5件で止まり、
> 25件を超えるのは2%未満。続いている例の特徴は「2人以上による長期のチーム活動」。**

**執事は1人（＋主人）です。** 統計的には**止まる側**にいます。

もう1つ:

> **ブックマークした場所は、していない場所より取り出しやすくならなかった**
> （n=50。階層メニュー経由の到達は4%）

主人が X で溜めているブックマークも、この研究の対象そのものです。
**「溜める」を機械化しても、同じ結末になります。**

→ だから **§8 の止め方**を先に決めておきます。

## 7. 手順（今夜から。1週間）

### 毎晩

1. **5件拾う。** キーワードは毎晩変える。**記事中の新しい語を翌晩の種にする**
2. 各記事の**視点を1〜3文**——「何をしているか」ではなく「**なぜそうしたか**」
3. **台帳（`02_research/外部視点の台帳.md`）を先に引く。**
   同じ視点が既にあれば、**行を足さずに既存へ「+1（日付）」**（§4）
3.5. ⚠ **ここで一度、素材5件を台帳へ書く**（判定を付ける**前**に。2026-09-06 追加・[[00_butler/GROWTH]] G72）。
   出どころ・日付・視点まで。判定と理由の列は**空のままでよい**——**次の手順で埋めます**。

   > **なぜ**: この定例は**上限60分の1かたまり**で、⚠ **前夜（2026-09-05）はその内側で夜勤が消え、
   > 4時間48分ぶんの記録が丸ごと残りませんでした**。G69（1本終えるごとに報告へ追記）は
   > 守られていましたが、**「1本」が大きすぎて追記の機会が来なかった**のです。
   > 外の言葉では**チェックポイントの粒度**——**呼び出しごとに書くと重すぎ、境界が遠すぎると失う**
   > （台帳 E21）。**5件拾い終えた時点が、この作業の自然な境界**です。
   > **落ちても「拾うところまでは終わった」が残り、次の晩が続きから始められます。**

4. 5件それぞれに判定を付ける:
   - **採用**（1件だけ）
   - **既にやっている** —— **どこで**（ファイル名か G番号）を必ず書く
   - **見送り** —— 理由を1行。「合わない」だけでは不可（PRISMA 16b と同じ扱い）
5. **採用した1件**は `GROWTH.md` へ。**打った手は実際にファイルを直すところまで。**
   そして **「いつまでに、何が観測できれば効いたと言えるか」を必ず書く**（§1）
6. **素材5件は台帳に1行ずつ残す**（出どころ・日付・視点・判定・理由）。**消さない**

### 週に1度（`/brief week` と同時）

**先週採用したものの「効いたか」を確かめる。** §1 で書いた観測が出たか。
出ていなければ **`GROWTH` の検証列に「効かなかった」と書く**——これも成果です。

## 8. 止め方を先に決める（主人の逓減案の置き換え）

主人は「1週間毎日 → その後は週1」を提案されました。
**調査では、この形の入口の逓減は**どの領域にも**見つかりませんでした**（無いことの証明ではない）。

そこで**日数ではなく結果で決めます**。1週間（7晩）が終わった時点で:

| 実績 | どうする |
|---|---|
| 採用 **3件以上**、かつ**うち1件でも効果が観測できた** | 毎晩を続ける |
| 採用 1〜2件、または**効果がまだ何も観測できない** | **週1回**へ落とす |
| 採用 **0件**、または「既にやっている」が**半分以上** | **止める。** 外から取る段階を過ぎている |
| **3晩以上、台帳が増えていない** | **止まっている。** §5 の検査が鳴る。仕組みの問題として扱う |

**「毎晩やること」を目的にしません。止めるのも結論です。**

> 変更済み（`docs/reports/外部視点の台帳.md` 参照）。
