# ADR-012 — カレンダー拡張（5d）と多言語対応（5h）

日付: 2026-09-05 ／ 状態: 採択 ／ 決めた人: 執事（Opus）

## 1. 背景

主人の指示「5d, 5h を進めてください」。第5期の残り4つのうち2つ。

- **5d** カレンダー拡張（ICS の読み取り）— 唯一残っている機能追加
- **5h** 多言語対応（ja/en）

### 順序についての注意

ロードマップでは 5h は 5g（「フォルダを触らせない」の総点検）の後だった。5g は
**画面に新しい文言を足す**作業なので、先に 5h をやると 5g の分をあとから訳し直すことになる。
主人の指示どおり進めるが、**5g で足した文言は必ず両方の言語に入れる**——D9 の検算試験が
落ちるので、忘れることはできない仕組みになっている。

---

## 2. 決定 — 5d カレンダー拡張

### D1 予定は `secretary_event` に入れる。**新しい表を作らない**

`secretary_event` は最初から `source`（`manual` / `ics` / `connector`）と `external_id` を
持っている。予定は秘書が預かるもので、出どころが違うだけの同じ概念である。新しい表を作ると
「次に来るもの」の答えが2つできる（ADR-011 D2 と同じ判断）。

### D2 取り込みは**一方通行**。外へ書き戻さない

読むだけ（HTTP GET のみ）。予定の作成・変更・削除は行わない。**外部送信ではない**ので
human_gate の対象にならない——これは「送信しないから」であって、拡張だからではない。

### D3 ICS の URL は**秘密の置き場**へ（`config.toml` に置かない）

Google・Outlook の非公開 ICS URL は**それ自体が鍵**である（知っていれば誰でも中身を読める）。
`config.toml` は④（環境固有）であって②（主人の情報）ではない。混ぜると、うっかり git に
入る経路ができる。よって `secret_fields: ["url"]`——API から読めず、`has_url` だけが見える
（ADR-009 D7 と同じ扱い）。

**カレンダーは1本から始める。** 家族ぶんを足したくなる可能性はあるが、いま必要なのは主人の
1本である。必要になってから足す。

### D4 依存を増やさない。**ICS は自前で解く**（2026-09-05 改訂: `tzdata` は例外）

コアにも拡張にも新しい pip 依存を入れない（「拡張が1つも入っていなくても manor は完全に
動く」の不変条件は、拡張自身が重くならないことでも支えられる）。ICS は
「75 オクテットで折り返された `KEY;PARAM=値:値` の並び」という単純な形式で、標準ライブラリ
（`urllib`・`zoneinfo`）だけで解ける——**という判断だったが、実装の検分（2026-09-05）で
誤りと分かった。** Windows は OS 自体に IANA のタイムゾーンデータベースを持たず、
`zoneinfo` は `tzdata`（コードを持たないデータのみの配布物。CPython の中の人が保守）が
無いと `UTC` すら解決できない（実機で `ZoneInfoNotFoundError` を確認）。

D4 の意図は「**ICS を解くための外部ライブラリを入れない**」であって、標準ライブラリが
仕様どおりに動くための必須データまで拒む趣旨ではない。「時刻がズレるかもしれないが
黙って進む」は manor が最も避ける形なので、`tzdata` を `pyproject.toml` の依存に無条件
（環境マーカー無し）で加えた。それでも解決できない TZID（滅多に無い地域・`tzdata` 自体が
入っていない実行環境）が残る可能性はあるので、**その場合の逃げ道は残す**——非対応の
RRULE と同じ作法で、ローカル時刻として扱ったことを `note` に残し画面から見える形にする
（黙って落とさない）。

対応する項目: `UID` `SUMMARY` `DTSTART` `DTEND` `LOCATION` `DESCRIPTION` `RRULE` `EXDATE`
`STATUS`（`CANCELLED` は取り込まない）。
時刻は `TZID=` 付き・`Z`（UTC）・終日（`VALUE=DATE`）の3つを扱い、**ローカル時刻に揃えて**
保存する（表は ISO 文字列）。

### D5 繰り返しは「よくある形」だけを、**期間を区切って**展開する（2026-09-05 改訂）

毎週の予定が出ないカレンダーは使えない。しかし RRULE の全対応は沼である。

- 対応: `FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`、`INTERVAL`、`COUNT`、`UNTIL`、`BYDAY`（WEEKLY のみ）
- 除外: `EXDATE` は取り除く
- 窓: **繰り返しの展開にだけ、今日から 90 日**。それより先の回は持たない（持っても
  使わない）。**単発の予定（繰り返しが無い予定・対応できない繰り返しの最初の1回も
  含む）には窓をかけない**——今日以降であれば上限なくすべて取り込む（初版は単発にも
  同じ窓をかけていたが、それだと4か月先に予約した旅行のような実在する予定を manor が
  持たなくなる誤りだったため、2026-09-05 に改訂した。際限なく増える原因は「終わりの
  無い繰り返し」だけなので、そこにだけ上限を置けば足りる）。過去（今日より前）は
  単発・繰り返し問わず取り込まない
- **対応できない繰り返しを黙って落とさない。** 最初の1回だけを取り込み、`note` に元の
  `RRULE` をそのまま書く。「出ていない予定がある」ことが画面から見える形にする

### D6 同期は明示的（`manor calendar sync`）。**冪等**

- 突き合わせの鍵は `external_id` ＝ `UID` ＋ 開始時刻（繰り返しの各回を別の予定として持つため）
- 既にあるものは更新、feed から消えたものは削除
- **`source='manual'` の予定には絶対に触らない**——主人が手で入れたものを同期が消すのは事故
- 夜勤への組み込みは**今回やらない**（夜勤の中身を変えるのは別の判断）

### D7 画面に出す

秘書のページに「予定」、ダッシュボードの「次に来るもの」に混ぜる。どちらも**既にある
問い合わせに足す**（新しい集計を作らない）。

## 3. 決定 — 5h 多言語対応

### D8 日本語が原文。英語は訳。**キーで引く**

日本語の文そのものを id にしない——文を直すたびに訳が全部外れる。短いキー（`nav.tasks`）で引く。

### D9 **抜けは試験で塞ぐ**（2026-09-05 追補: 呼び出し側も型で塞ぐ）

ja と en のキー集合が**完全に一致する**ことを機械で検算する。訳し忘れたら試験が落ちる。
画面にキーが露出する（`nav.tasks` と表示される）ことを許さない。**これが 5h の本体である**
——訳文そのものより、抜けない仕組みのほうが長く効く。

**追補（検分 2026-09-05）**: 辞書の抜けを塞いでも、**呼び出し側の引数漏れ**は素通りした。
差し込みのある文言を引数なしで呼び、画面に `undefined` が出た（日本語側も壊れていた）。
辞書は正しいので検算試験は緑のまま——**穴は辞書ではなく呼び出しにあった**。

よって `t()` の型を、値が関数の項目では引数を必須にした。渡し忘れは `tsc` で落ちる。
残る限界も記しておく: **渡した引数の名前**が正しいかまでは型で見ていない（`Params` が
緩い型のため）。引数そのものの渡し忘れは塞いだが、名前の取り違えは塞げていない。

### D10 置き場は画面と CLI で分ける

- 画面: `web/src/app/i18n/{ja,en}.ts` ＋ `useT()`
- CLI: `src/manor/i18n/{ja,en}.json` ＋ `t(key, **kw)`
- **キーの空間は共有しない。** 画面と CLI は語彙が違い、共通化すると片方の都合がもう片方を歪める

### D11 選び方は `[manor] language`

`auto` / `ja` / `en`。既定は `auto`＝ブラウザ・OS の設定に従い、分からなければ `ja`。
設定画面（右上の歯車）に置く。

**`[web]` ではなく `[manor]` という新しい節にする**——言語は画面だけのものではなく、CLI の
出力にも効くため。CLI は `MANOR_LANG` 環境変数を最優先で見る（一度きりの切り替え用）。

### D12 訳さないもの

- 主人が入れたデータ（タスク名・プロジェクト名・呼び名・メモ）
- **担当の名前は訳す**（執事 → Butler、料理長 → Chef …）——製品の一部だから
- 日付・時刻の書式はロケールに従う——**実装ではここを狭めた**（2026-09-05 検分）。
  `Intl` の整形は用意したが、適用は一部に留めた。`2026-09-05` の形は英語圏でも誤解なく
  読め、見出しの「本日／Today」は訳せている。全面適用は既存試験の広範な書き直しを
  伴い、得られるものに見合わない。**画面の日付は ISO のままとする**

### D13 範囲を2段に切る

| 段 | 何 | 今回 |
|---|---|:--:|
| **5h-1** | **画面の文言すべて** ＋ 切り替えの仕組み ＋ D9 の検算試験 | ✅ 2026-09-05（訳語 641・検算3種） |
| **5h-2** | CLI の出力（結果行・エラー文）と `--help` | 次 |

**理由**: 主人の方針は「インターフェースは基本的に Web アプリ経由」（ROADMAP 11-1）。
英語話者が最初に触るのも画面である。CLI の `--help` は 40 近いサブコマンドぶんあり、
画面と同じ回で混ぜると、どちらも中途半端に終わる。**5h-1 を完成させてから 5h-2 に入る。**

---

## 4. やらないこと

- 予定の書き戻し（D2）
- 複数カレンダー（D3。必要になってから）
- RRULE の完全対応（D5。対応できないものは見える形で残す）
- 夜勤への同期の組み込み（D6）
- 日本語・英語以外の言語（枠組みは足せる形にするが、訳は作らない）
- CLI の翻訳（D13。5h-2 へ）
