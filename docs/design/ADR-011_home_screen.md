# ADR-011 — 総括ダッシュボード・担当の一覧・小窓の作り直し

日付: 2026-09-04 ／ 状態: 採択 ／ 決めた人: 執事（Fable）

## 1. 背景

主人のフィードバック（2026-09-04・実機を触って）。7点あるが、**「manor に入って最初に見る場所が無い」**と**「小窓が v1 から機能を落としている」**の2つに分かれる。

| # | 指摘 | 分類 |
|---|---|---|
| 1 | 小窓の上部にヘッダが出る（v1 では出なかった） | 小窓 |
| 2 | 口が動いていない（リップシンクは？） | 小窓 |
| 3 | ピン留めが消えている | 小窓 |
| 4 | 小窓を開くボタンが設定にしかない | 入口 |
| 5 | 担当の一覧が欲しい（VRM 付きカード・名前と役職・担当ページへ） | 入口 |
| 6 | 総括のダッシュボードが欲しい。サイドバーの先頭に置き、次に担当一覧、その下にタスク・台所… | 入口 |
| 7 | 設定は右上のアイコンへ | 入口 |
| 8 | Web アプリ起動のショートカット（5f）を早めに | 運用 |

### 訂正: v1 の「口」と「ピン留め」は実装済みだった

ADR-008 §4 に「小窓の口を動かす（**v1 でも未実装**）」と書いたのは**誤り**である。v1 の README の古い一文（「口はまだ動きません」）だけを見て判断した。実際には:

- `apps/butler-board/src/butler_board/face_speech.py`（174行）— VOICEVOX の `audio_query` が**合成の前に**モーラごとの母音と長さを返すので、「いつ・どの口の形になるか」は再生前に全部分かる。それを cue の列（予定表）に変換する
- `static/face-mouth.js` — 予定表どおりに VRM の口の形（`aa`/`ih`/`ou`/`ee`/`oh`）を動かす。**別ファイルにしてある**（ここが壊れても 3D の描画は無事）
- `face_pin.py`（91行）— ブラウザからは窓の重なり順を変えられないので、**ページからの操作をサーバが受けて Windows の API で最前面に固定**する。窓は題名で探す

**教訓**: 移植の棚卸しで「v1 に無い」と書くときは、README ではなく**コードを見る**。

## 2. 決定 — 入口

### D1 サイドバーの並びを主人の指定どおりにする

`ダッシュボード` → `担当` → `タスク` → `台所` → `家事` → `家計` → `秘書` → `ルール` → `取り込み` → `夜勤` → `拡張機能`。**設定はサイドバーから外し、右上のアイコンにする**（歯車。押すと `/settings`）。

数字キーの割り当ては並び順のまま（1がダッシュボード）。

### D2 ダッシュボード（新規・サイドバー先頭）

**すべての統括**。主人が朝いちばんに開く場所。参考にした画面（主人が共有）に倣うが、**中身は manor の事実に置き換える**。

| 帯 | 出すもの | 出どころ |
|---|---|---|
| 状態の一行 | 「問題ありません」または要対応の件数・失敗の件数 | `check` の警告以外／`v_blocked_ready`／open decision |
| 数字の並び | 判断待ち・進行中・今日期限・今週の完了・夜勤の最終結果 | `render.active_data` と `task_event` |
| 次に来るもの | 直近のマイルストーンと期限（時刻つきで横に並べる） | `milestone`・`task.due` |
| 24時間の帯 | 実行の成否を時刻で並べる（`run` 表。緑＝成功・赤＝失敗） | `runlog.list_runs` |
| 要確認 | open decision（無ければ「問題はありません」） | `decision` |
| よく動いているもの | 直近7日の実行回数が多い順（棒） | `runlog.stats` |
| 稼働と費用 | 24時間の実行回数・成功率・費用（**計測できた件数を併記**。ADR-006 D23） | `runlog.stats` |

**新しい数字を作らない。** 既にある問い合わせを並べ替えて見せるだけ——ダッシュボード専用の集計を足すと、同じ問いに二つの答えができる。

### D3 担当の一覧（新規・サイドバーの2番目）

カードを並べる。1枚 ＝ 1担当。

- **姿**（`/face/model.vrm?agent=<id>` を静止画として見せる。無ければ輪郭）
- **名前と役職**（執事／料理長／家政婦／家令／秘書／検分／監査）
- **何を預かるか**の一行（`docs/staff/*.md` の要旨。マニフェスト的に持つ）
- **担当のページへ**（執事→タスク、料理長→台所、家政婦→家事、家令→家計、秘書→秘書。qa/auditor は行き先が無いので出さない）
- **小窓を開く**（D5）
- **導入されているか**（部下の表があるか。`meta.modules` の `enabled` と同じ判定）

### D4 小窓を開く口を増やす

いまは設定の中だけ。**担当の一覧の各カード**と**ダッシュボード**からも開ける。

## 3. 決定 — 小窓

### D5 ヘッダを消す = ブラウザの窓ではなく Chrome のアプリモードで開く

`window.open` のポップアップには題名の帯が付く。**JS からは消せない。** v1 は Chrome の `--app=` で開いていた（`manor face` と同じ）。

- **`POST /api/v1/face/open`** を足す。サーバが `manor face` と同じ経路で Chrome をアプリモードで起こす（サーバは主人の PC で動いているので開ける）
- 画面のボタンはこれを呼ぶ。Chrome が見つからないときだけ `window.open` のポップアップに落とし、**その旨を伝える**
- `require_writable` は課さない（窓を開くのは書き込みではない）が、**認証の内側**に置く（`/api/v1/` の一般規則）

### D6 リップシンク（v1 `face_speech.py` ＋ `face-mouth.js` の移植）

**声を出すときだけ動く。** VOICEVOX が未設定なら何も起きない（口は閉じたまま）。

- `voice.speak` が合成するとき、`audio_query` の結果から**口の形の予定表**（`[{at_ms, viseme, weight}]`）を作る。`audio_query` は合成の前に返るので、**再生開始と同時に予定表を渡せる**
- 予定表は `GET /api/v1/face/mouth` が返す（小窓が短い間隔で取りに来る／または `POST /talk` の応答に同梱する。**実装は前者**——声は通話以外でも鳴る）
- 動かすのは**別ファイル**（`face_static/face-mouth.js`）。v1 の作法どおり、**ここが壊れても 3D の描画は無事**
- 母音→表情の対応と無声化の扱いは v1 の表をそのまま使う（`a→aa` `i→ih` `u→ou` `e→ee` `o→oh`、`N`/`cl`/`pau` は閉じる）

### D7 ピン留め（v1 `face_pin.py` の移植）

ブラウザからは窓の重なり順を変えられない。**ページの操作をサーバが受け、Windows の API で最前面に固定する。**

- `GET /api/v1/face/pin` → `{supported, pinned}`／`POST /api/v1/face/pin {pinned: bool}`
- 窓は**題名で探す**（`<title>` は担当の日本語名。ダッシュボードとは別の題名なので取り違えない）
- **Windows 以外では `supported: false`** を返し、画面はボタンを出さない（できないものを出さない）

## 4. 決定 — 運用

### D8 起動のショートカット（ROADMAP 5f。主人が「早めに」と指定）

**毎回コマンドプロンプトで `uv run` させない。**

- `manor shortcut create` — デスクトップに「manor を開く」を作る。中身は**ビルド → サーバ起動 → ブラウザを開く**を1つにしたもの
- **サーバが既に動いていれば起こし直す**（更新を反映するため。主人の「サーバーを再起動して更新する際に毎回コマンドプロンプトで uv run するのは面倒」がこの機能の理由）
- Windows は `.lnk`（PowerShell の `WScript.Shell` で作る）、macOS は `.command`、それ以外は `.desktop`。**OS 固有スクリプトをリポジトリに置かない**——作るのは主人の環境の中だけ
- `manor shortcut remove` / `manor shortcut status`
- 初回セットアップの最後に「デスクトップにショートカットを作りますか」を置く（既定は作る）

## 5. やらないこと

- ダッシュボード専用の集計（D2）
- 担当ごとのペルソナ切り替え（通話は執事のまま。別 ADR）
- ピン留めの Windows 以外への対応（できないものを装わない）

## 6. 担当ごとの声（2026-09-05・主人の依頼）

> 家事担当を女性アバターで作りましたが、声が執事と同じなのが気になりました。

姿は担当ごとに持てるのに（D3）、**声は1つしか無かった**。姿と声は同じ「その担当らしさ」の一部なので、置き場も揃える。

### D9 話者は担当ごとに持てる。既定は1つ

`home/config.toml`:

```toml
[voice]
engine = "voicevox"
speaker = 13            # 既定（担当ごとの指定が無いときに使う）

[voice.speakers]        # 担当ごとの上書き（省略可）
housekeeper = 46
chef = 3
```

- 解決の順は **`[voice.speakers].<agent>` → `[voice] speaker`**。担当を指定しない呼び出し（`manor voice say` 等）は既定を使う
- **wav キャッシュの鍵には既に話者IDが入っている**（`sha256(text|speaker)`）ので、担当ごとに声が違っても混ざらない。作り直しも要らない
- `manor voice say "<text>" [--agent <name>]` / `manor voice warm [--agent <name>]`（既定は全担当ぶん作り置き）

### D10 画面は拡張機能のカードがそのまま使える

`voicevox` のマニフェストに**担当ごとのフィールドを並べる**（`speaker_<agent>`。`options_from: "speakers"` なので D17 の2段選択がそのまま効く）。**新しい画面を作らない**——拡張機能のフォームは `fields` から自動で組まれる。

- 先頭は既定（`speaker`。ラベル「既定の話者」）、続けて担当ごとに「執事の声」「家政婦の声」…
- 担当ごとの欄は**任意**。空なら既定を使う（フォームの補助文にそう書く）
- 保存は `[voice.speakers]` へ。`speaker_housekeeper` → `[voice.speakers] housekeeper`

### D11 声を出す側は担当を渡す

- `voice.speak(home, text, *, agent=None)`。`agent` が無ければ既定
- **小窓の通話は窓の担当の声で返す**（`/api/v1/face/talk` は既に `agent` を知っている）。姿が家政婦なら声も家政婦
- **通話を開いた瞬間の挨拶も担当の声**（`/api/v1/face/talk/open` も `agent` を受ける）。姿が家政婦なのに最初のひとことだけ執事の声、では揃わない——「返事だけ」に絞ると、主人が最初に聞く声が既定のままになる（2026-09-05 追補）
- `manor notify`（声かけ）は執事の声（`agent="butler"`）

**人格までは切り替えない。** 中身は執事のまま（ADR-008 §8 D21）。ここで揃えるのは**声と姿**だけで、誰が答えているかの設計は別に決める。
