# T11 — powercfg /lastwake にタスク名が出るかの実測

## 経緯

`--sleep-back`（`src/manor/night/runner.py` の `woken_by_task()`）は、直近の復帰が
`manor-night` タスクのウェイクタイマーによるものかを `powercfg /lastwake` の出力に
タスク名が含まれるかで判定する。2026-09-06 時点でこの判定がタイマー復帰で
一度も確かめられていなかった（手元は復帰履歴0件のみ）。

## 2026-09-14 02:31 の実測

- `schtasks /Query /TN manor-night /V /FO LIST` → `Last Run Time: 2026/09/14 2:00:01`。
  今回の夜勤（02:00:02開始）と一致——タスクスケジューラ経由の起動を確認
- `schtasks /Query /TN manor-night /XML` → `<WakeToRun>true</WakeToRun>` を確認
- `woken_by_task()` を直接呼び出した結果: `woken: false`、
  `detail`: 「スリープ状態の解除履歴カウント - 1 / スリープ状態の解除履歴 [0] /
  スリープ状態の解除元カウント - 0」——解除元の詳細情報自体が記録されていない
- `home/night/logs/2026-09.log` を遡ると、09-06〜09-14 まで**9夜連続**ですべて
  「眠りません: この復帰は執事のタスクによるものではありません」

## 根本原因

`powercfg /query SCHEME_CURRENT SUB_SLEEP` を実行すると、**AC電源時の自動スリープ
（STANDBYIDLE）のインデックスが `0x00000000`（なし＝無効）**。つまりこのPCは
AC電源に繋がっている間、自動的にスリープすることが無い。02:00のタスク起動は
毎晩「PCが起きたままの定時実行」であり、「スリープ→タイマー復帰」という
シナリオそのものが一度も発生していない。`RTCWAKE`（スリープ解除タイマーの許可）
自体は「有効」——ウェイクタイマーの許可は問題ない。

## 結論・次の一手

「タスク名が `powercfg /lastwake` に出るか」はまだ**判定不能**（出ない、とは
まだ言い切れない——検証できる状況が一度も発生していないだけ）。判定するには
AC電源の自動スリープを一時的に有効化し、実際にスリープ→タイマー復帰を
1回発生させる必要がある。電源設定の変更は日中の主人の作業に影響しうるため、
`manor decision ask` へ積んだ（D番号は決定欄を参照）。
