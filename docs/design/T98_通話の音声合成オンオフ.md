# T98 通話窓口: 音声合成のオン/オフ

## 背景

意見箱（Slack #idea）: 「通話で音声合成の応答が遅く感じる。長文を毎回全文合成すると
時間がかかるので、テキストだけで良い場面ではオン/オフを選べるようにしたい」。

## 原因の切り分け（2026-09-25夜勤・N-list T98で確認。実測ではなくコード読解）

`src/manor/talk_session.py` の `ask()`（プロンプト応答を作る本体）:

```python
reply = str(data.get("result") or "").strip()
...
spoken = voice.speak_detail(home, reply, agent=agent, play=not play_here)  # 859行目
return {"ok": True, "reply": reply, ...}
```

**`reply`（テキスト本文）は`voice.speak_detail()`を呼ぶ前に既に確定している。**
にもかかわらず、関数は音声合成（`_ensure_cached`→エンジン未起動なら`engine_start`で
最大60秒待ち・`audio_query`最大30秒・`synthesis`最大120秒）が終わるまで**返信全体を
返さない**——ブラウザ側は音声が出来上がるまでテキストも見られない。

**結論: 音声合成が遅延の主因という意見箱の指摘は、コード上でも裏付けが取れた。**
特に「エンジンが眠っていた直後の1往復目」は最大で数十秒余計に待たされる計算になる
（`engine_start`の起動待ち上限60秒 + 合成）。

## 設計（未実装。次の担当が実装する前提）

`TalkAskRequest`（`src/manor/web/api_v1/face_talk.py`）に `voice: bool = True` を足し、
`talk_session.ask()` に渡す。`voice=False` のときは `voice.speak_detail()` を**呼ばず**、
`audio_id=""` のまま即座に `reply` を返す——テキストだけで良い場面はここで速くなる。

- 画面（`face.html`）側にオン/オフの切替（トグル）を1つ持たせ、`talk_ask` の body に
  `voice` を乗せる。既定は `true`（今までどおり）——**黙っていたら壊れない**。
- `voice=False` でも `WAIT_LINE`（T57）は今までどおり出してよい（あちらは Claude 呼び出し
  自体の待ち時間の話で、今回の遅延源とは別の場所）。
- キャッシュ命中時（`wav_path.is_file()`）は合成そのものが速い（エンジンにも触れない）ので、
  体感が特に悪いのは「初回・未キャッシュの長文」——ここが`voice=False`の主な効き所になる。

## 実装を今夜見送った理由

`src/manor/talk_session.py` は今夜の時点で**T57（`WAIT_LINE`）の未コミット差分**が
既に乗っている。同じファイルへ夜勤が別件で書き加えると、日中の作業者が戻ってきたときに
2つの変更が絡まって読みにくくなる。**原因の切り分けと設計はここまでとし、コードの追記は
次の担当（T57が片付いたあと）に譲る。**
