# ADR-010 — 初回セットアップの作り直しと「タスクの種類」

日付: 2026-09-04 ／ 状態: 採択 ／ 決めた人: 執事（Fable）

## 1. 背景

主人が初回セットアップを実際に触って出したフィードバック（2026-09-04）。**8点すべてが「作った側にしか意味が分からないものを、初めての人に見せている」という一点に集約される。**

| # | 指摘 | 何が起きているか |
|---|---|---|
| 1 | 入力欄が重なっている | 見た目の不具合 |
| 2 | プロジェクトの期限とは。普通プロジェクトに期限は設けない | 執事の都合の項目を聞いている |
| 3 | 「プロジェクト」が何か分からない | 語の説明が無い |
| 4 | プリセットに説明が欲しい | 同上（🐢🚶🏃 だけでは伝わらない） |
| 5 | タスクにも説明が欲しい | 同上 |
| 6 | 行動クラスが分からない。種類を示すなら抽象的・一般的な分類にすべき。**Web から編集したい** | **執事の内部語彙をそのまま見せている** |
| 7 | 期限のないタスクも受け取れるように | 任意なのに必須に見える |
| 8 | 各画面の先頭に「ここで何をするのか」が要る | 画面の入口が無い |

## 2. 決定

### D1 「行動クラス」は初回セットアップから外す

行動クラス（`butler/policy.toml` の `[classes]`）は**自律の度合い（level）を決める機構**であって、タスクの種類ではない。初めての人が向き合うものではない。

- **セットアップでは聞かない。** 既定 `general`（L2）で起票する
- 執事が自分で起票するときは従来どおり `--class` を使う（CLAUDE.md の原則は変えない）
- 「行動クラス」という語を主人向けの画面から消す。残すのは執事の道具（CLI・`--help`）の中だけ

### D2 「タスクの種類」を新設する（人に意味がある分類）

主人が見るのはこちら。**機構的な意味を持たせない**——並べ替え・絞り込み・振り返りのための札である。level とは無関係。

- `task.kind TEXT NOT NULL DEFAULT ''`（列を追加。`db.init` の冪等な移行で足す）
- 語彙は `task_kind` 表に持ち、**Web から足す・名前を変える・隠すができる**（指摘6の後半）

既定の8つ（`manor init` が入れる。**多すぎないこと**を主人が指定）:

| id | 表示 |
|---|---|
| `research` | 調査・情報収集 |
| `design` | 検討・設計 |
| `build` | 作成・実装 |
| `fix` | 修正・改善 |
| `write` | 資料・文章の作成 |
| `contact` | 連絡・調整 |
| `admin` | 手続き・事務 |
| `other` | その他 |

- `other` は**消せない**（分類できないものの受け皿。消せると「種類が無い」状態が表現できなくなる）
- 隠す（`archived_at`）はできるが、既にその種類が付いた task はそのまま残る——**過去の記録を書き換えない**
- `task.kind` が空でもよい。**種類は必須ではない**

### D3 プロジェクトの期限は聞かない

主人の言うとおり、プロジェクトに期限を設けるのは普通ではない。期日はマイルストーン（`milestone`）で表す。

- `project.due` の列は残す（v1 からの取り込みが使う）が、**セットアップの画面からは外す**
- 代わりに「期限のあるものは、あとから節目として足せます」の一行を置く

### D4 語には説明を添える

**画面に出す説明は、その場に置く。** README を読ませない（ADR-009 D7 と同じ姿勢）。

| 語 | 説明（画面に出す文） |
|---|---|
| プロジェクト | 関連するタスクをまとめる入れ物です。登録しておくと、タスクの紐づけと全体の進み具合を執事が引き受けます。 |
| タスク | ひとつの完結した作業です。**期限は無くても構いません。** |
| 自律レベル（旧「プリセット」） | 執事がどれくらい自分で判断して進めるかの目安です。慎重＝確認を多めに取る／標準／高速＝任せる範囲を広げる。あとから変えられます。 |
| タスクの種類 | あとで振り返るための分類です。迷ったら「その他」で構いません。 |

プリセットと種類の説明は**選択欄の下に常に出す**（フォーカス時だけだと、触る前に読めない）。

### D5 期限は「無くてよい」と画面で言う

`due` は元から NULL 可（スキーマ上すでに任意）。**画面がそう見えていないだけ**。

- ラベルを「期限（任意）」にし、補助文に「決まっていなければ空のままで構いません」
- 確認の段では、空の期限を「—」ではなく**行ごと出さない**（無いものを見せない）

### D6 入力欄の重なりを直す

`.setup-row` の折り返しで、ラベルと入力が重なる。**複数の幅で実物を見て直す**（少なくとも 1280 / 1024 / 860 / 600 px）。直したあと、同じ幅で「重なりが無いこと」を機械で検算する試験を置く（要素の矩形が交差しないこと）。

### D7 どの画面にも先頭に「ここで何をするか」

共通の見出し部品を作り、**全モジュールの先頭に置く**。

- 画面名（大きく）と、**一行の説明**（何をする場所か）
- 例: 「タスク — いま抱えている仕事の一覧です。要対応から片づけます。」／「拡張機能 — 外部のアプリやサービスをつなぎます。」
- 初回セットアップの各段にも同じ形で置く（段の題＋一行）

## 3. やらないこと

- 種類から level を自動で決めること。**種類は札であって門ではない**（混ぜると、主人が種類を変えただけで執事の自律の度合いが変わってしまう）
- 既定の8つを主人の使い方に合わせて増やすこと。**足りなければ主人が Web から足す**（それができるようにするのが D2）

## 4. 試験

- `tests/test_task_kind.py`: 既定の8つが入る・`other` は消せない・隠しても既存 task の `kind` は変わらない・語彙外の `kind` は拒む・`kind` は空でよい
- `tests/web/test_task_kinds.py`: 一覧・追加・改名・アーカイブの経路、`--read-only` で 403
- `tests/web/test_setup.py`: セットアップの body に `cls` が無くても通る（既定 `general`）／`due` を省いた project・task が作れる
- `web/src/modules/setup/Setup.test.tsx`: 行動クラスの選択欄が**無い**こと／説明文が出ていること／期限が任意であること
- `web/src/.../ScreenHeader.test.tsx`（または既存の各モジュール試験）: 全モジュールの先頭に見出しがあること——**登録簿を回して機械で検算する**（1つ足したときに忘れない）
- レイアウト: 複数幅で `.setup-row` の要素矩形が交差しないこと


## 5. 実機での追加フィードバック（2026-09-04・主人が本番で確認）

| 指摘 | 裁定 |
|---|---|
| 「プリセット」を「自律レベル」に | 改名した。**主人の画面から絵文字も外す**（🐢🚶🏃 は執事側の文書には残すが、選択肢のラベルは文字だけ） |
| タスクの種類が0件で選べない／確認画面で500 | **原因は古いサーバのプロセス**（更新後に止め忘れ）。`meta.stale` は真だったが、**警告の帯が枠側にしかなく、初回セットアップの画面でだけ隠れていた**——初めての人が最初に見る画面である。セットアップにも帯を出す |
| プロジェクトの記号で `P1` が弾かれる | 見た目の制約ではなく実害の回避だった（`P` で始まる参照は project の **id** として先に解決されるので、`P1` という記号は自分の id に隠される。`project.resolve`）。**弾かずに黙って小文字へ揃える**。欄の下に「小文字に揃えます」 |

**学び**: 「動かない」の原因が古いプロセスなら、それを告げる場所は**最初に開く画面**にも要る。枠の中だけに置いた警告は、枠を持たない画面（セットアップ・ログイン）では消える。
