目的: 「AI執事に何をやらせるのが正解か」を判断するための選択肢の全体像。
主に OpenClaw（38万Star）ユーザーの実運用例、国内活用記事、コミュニティ集から収集。

## 実現方式は5パターンしかない

どのユースケースも、実現方法は以下の組み合わせに分解できる:

| 方式 | 内容 | 例 |
|------|------|-----|
| ①指示型 | チャットで都度依頼 → 実行して報告 | 「このPDF要約して」 |
| ②定期実行型 | cron / Heartbeat で決まった時刻に自動実行 | 朝7時のブリーフィング |
| ③監視型 | ポーリング/Webhookで変化を検知 → 条件を満たしたら通知・行動 | 「日経平均が2%動いたら原因を調べて報告」 |
| ④委譲型 | 親エージェントがサブエージェントに並列委譲 | PRレビュー+Issueトリアージ+CI監視 |
| ⑤LLM+スクリプト分業 | 確定的な処理はスクリプト、判断と文章だけLLM | メール判定はシェルスクリプト、要約だけLLM（コスト90%減の実例） |

実運用の知見: **定期実行は Heartbeat よりOSのcronが確実**。「何をすべきか」はプロンプトでなく設定ファイル(JSON/Markdown)に書いてバージョン管理する。

## カテゴリ別ユースケース一覧

### A. 情報収集・ブリーフィング（読み取り専用・最初にやるべき定番）

| ユースケース | 内容と実現方法 | 方式 |
|---|---|---|
| **朝のブリーフィング** | 今日の予定+未読重要メール+天気+夜間アラートを毎朝1通のメッセージに集約してスマホへ。「毎日15〜25分の節約」が定番の効果 | ② |
| 業界ニュース監視 | 指定キーワードのニュースを毎日チェック、重要なものだけ通知（フィルタリング配信） | ②③ |
| マルチソース技術ダイジェスト | RSS/X/GitHub/Reddit/YouTubeなど100超ソースから興味に合わせて日次まとめ | ② |
| GitHubリポジトリ監視 | 注目リポジトリのスター数・最新コミットを毎朝報告 | ② |
| 株価・為替アラート | 「前日比2%以上動いたら原因を調べて報告」。閾値判定+調査+報告のセット | ③ |
| 競合・市場動向監視 | 競合他社サイトやSNSの変化を定期巡回して差分報告 | ③ |

### B. メール・メッセージ処理（効果最大と言われる領域）

| ユースケース | 内容と実現方法 | 方式 |
|---|---|---|
| **メールトリアージ** | 優先度・トピック分類、要返信の仕分け、定型問い合わせの返信下書き、緊急フラグ。「killer app」と呼ばれ週数時間の節約報告多数。**送信は人間が押す** | ②⑤ |
| 緊急メール即時アラート | 15分ごとにチェック。送信者・件名キーワードでスクリプト判定し、該当時のみLLM起動（コスト最適化の好例） | ③⑤ |
| 会議議事録の要約 | 会議音声/トランスクリプトから要約+アクションアイテム抽出+担当者別整理+出席者へ配布 | ① |
| 荷物追跡 | 注文確認メールから追跡番号を自動抽出→配送APIを照会→全荷物のステータス一覧を維持 | ③ |

### C. タスク・プロジェクト・スケジュール管理（★本プロジェクトの当面の本命）

| ユースケース | 内容と実現方法 | 方式 |
|---|---|---|
| **タスク抽出** | チャット/メールの依頼文から「誰が・いつまでに・何を」を構造化抽出、相対日付→絶対日付変換、期限48h/24h前リマインド | ③ |
| **プロジェクト横断ダッシュボード** | 複数プロジェクトの状態をMarkdown/JIRAから合成し俯瞰ビューを維持。切り替え時に「前回どこまで・何が変わった・次に何を」を要約 | ①② |
| 週次レビュー/KPI定期投稿 | 「毎週金曜17時に今週のKPIをSlackに投稿」。週次サマリ生成の完全自動化 | ② |
| スケジュール調整代行 | 空き時間確認→打ち合わせ候補3つ提示。相手への送信は人間 | ① |
| 目標駆動タスク生成 | 大目標から日々のタスクを自動生成・実行・進捗管理（Goal-Driven Autonomous Tasks） | ②④ |
| Personal CRM | メール・カレンダーから人間関係（誰といつ会った・次のフォロー）を自動追跡 | ③ |
| 習慣トラッキング | Telegram等で日次チェックイン、習慣の継続を執事が伴走（accountability coach） | ② |

### D. リサーチ・文書作成

| ユースケース | 内容と実現方法 | 方式 |
|---|---|---|
| 競合調査レポート | 「競合3社をWebリサーチして比較表をWordで保存」。半日→確認1時間の実例 | ① |
| 論文・長文読解 | arXiv論文の対話的読解、PDFの3行要約、契約書の重要条項抽出 | ① |
| スクレイピング整理 | 「求人情報10件をスプレッドシートに整理」等の一括収集 | ① |
| 文書ドラフト | 返信案・ブログ・資料・LaTeX論文の下書き生成 | ① |
| Excel集計・月次レポート | 集計はPythonスクリプトに移譲し、解釈と文章化だけLLM（2時間→30分の実例） | ①⑤ |

### E. 開発・DevOps（DevBotエコシステムの実例＝執事→子エージェント構成の手本）

親エージェント1体の下に専門サブエージェント5体を編成した実運用例:

| サブエージェント | 役割 |
|---|---|
| PR-Reviewer | コード変更の自動レビュー（静的解析・セキュリティ・スタイル） |
| Issue-Triager | 新規Issueを日次でP0〜P3に分類し自動ラベル付け |
| Dependency-Auditor | 週次でパッチ更新を自動マージ、**メジャー更新のみ人間承認待ち** |
| CI-Monitor | ビルド失敗を分類、フレーキーテストは自動再実行 |
| CodeMod | AST解析による大規模コード移行 |

その他: セルフヒーリングなホームサーバ管理（SSH+cron）、n8n連携（認証情報をエージェントに触らせない設計）

## 選定ガイド

### 何から始めるかの原則

1. **頻度が高く、毎回同じ形で痛いもの**から（朝の情報収集、プロジェクト切り替え）
2. **読み取り専用 → ローカル書き込み → 外部送信** の順にリスクを上げる
   （メール送信・購入・投稿を伴うものは最後。下書きまでで止めるのが定石）
3. 定期実行1本（朝ブリーフィング）+ 指示型数本 から始め、効いたものだけ自動化を深める

### 主人の現状に効きそうなトップ候補（執事の見立て。v1時点）

| 候補 | 対応する痛み | 必要なもの |
|---|---|---|
| 1. JIRA横断の朝ブリーフィング | 3〜4並行PJの全体像喪失 | JIRA MCP（接続済み）ですぐ試せる |
| 2. プロジェクト切替時のコンテキスト復元 | 「どこまでやったっけ」 | tasks/PROJECTS.md の運用開始 |
| 3. タスク抽出+期限リマインド | 非構造なタスクリスト | AGENTS.mdへのルール化 |
| 4. 週次レビュー自動生成 | 全体像の定点観測 | 上記2つの上に載る |
| 5. メールトリアージ（下書きまで） | （要ヒアリング） | Gmail連携 |
