# T71 下位エージェントの「曖昧だった点」が拾われず溜まるだけ

## 背景

`manor handoff report` は報告に `REPORT_HEADINGS`（`src/manor/handoff.py`）の見出しを必須化しており、
その1つが「曖昧だった点」（担当者定義で分かりにくかった箇所の指摘）。v1 には
`agents/改善サイクル.md` + `agents/<名前>/BACKLOG.md` があり、これを拾って `.claude/agents/*.md`
を計画的に育てる運用があった（T47 検分・`home/night/reports/2026-09-18.md`）。v2 では
見出しの必須化だけが移植され、**拾って反映する側**が無い。

## 今夜確認したこと（コード読解のみ・実装はしていない）

- `manor handoff report <id> --file <report.md>` は本文全体を `handoff.report` 列（自由文字列）に
  そのまま保存する（`src/manor/handoff.py` `report()`）。見出しの有無だけ検査し、中身は解析しない。
- `manor handoff list` は一覧（`verdict`・`task_id`・`agent` 等）を出すが、`report` 本文の
  「曖昧だった点」節だけを抜き出す口は無い。
- `/retro` スキル（`.claude/skills/retro/SKILL.md`）は**執事自身**（SOUL/AGENTS/POLICY/CLAUDE.md/
  skills/settings.json）だけを対象にしており、下位エージェント（chef/housekeeper/steward/secretary
  等）の `.claude/agents/*.md` は対象外。

## 選択肢

1. **`/retro` の対象を下位エージェントにも広げる**——1周で執事か下位エージェント1人かを選び、
   後者なら直近の `handoff.report` から「曖昧だった点」節を集めて `.claude/agents/<名前>.md` を
   改訂する。既存の `/retro` の「観測→改訂→GROWTH.md記録」の型をそのまま使い回せる。
2. **専用の新しいコマンド/スキルを作る**（v1の改善サイクルの再現）。`/retro` と役割が重複するため
   見送り候補。
3. **何もしない**（曖昧さの指摘は委譲のたびに読み返すだけで済ませる）。既に複数件溜まっている
   实績（chef/housekeeper 双方で指摘あり）から見送りは非推奨。

## 推奨

**選択肢1**（`/retro` の対象を下位エージェントにも広げる）。理由:
- 「観測して自分の規則を直す」という型が既にあり、対象を増やすだけで済む
- 新しい仕組みを増やすと、また「どっちに書くか」の分岐が増える（①層の肥大化を招く）

## 実装（次の担当向け・未着手）

1. `.claude/skills/retro/SKILL.md` に「対象＝執事 or 下位エージェント1名」を選ぶ分岐を足す
   （下位エージェントを選んだ周は `.claude/agents/<名前>.md` だけを改訂対象にする）
2. 集める材料: `SELECT report FROM handoff WHERE agent = ? ORDER BY id DESC LIMIT N` の
   「曖昧だった点」節（`manor handoff show <id>` で読める。専用の抽出コマンドは今のところ無い
   ——1周のたびに数件読む程度なら、素の `manor handoff list`/`show` で足りる）
3. 改訂したら `butler/GROWTH.md` に「下位エージェント◯◯の改善サイクルを回した」と記録
4. `.claude/` は夜勤が書けない領域のため、この実装は昼間に行う
