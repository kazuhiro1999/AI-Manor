# 試験の地図

`uv run pytest`（既定で並列。実測 23〜24秒／1,716件）。1本を追うときは `-n 0` で直列に。

束で回すときは `-m <カテゴリ>`。印は `tests/conftest.py` の `TEST_CATEGORIES` が
**パスから機械的に付ける**——各ファイルには書かない（1つの事実は1箇所に）。

| カテゴリ | 件数 | 何を見ているか |
|---|---:|---|
| `core` | 330 | DB・状態機械・グラフ・射影・整合検査・台帳。`manor` の背骨 |
| `presence` | 322 | 姿と声——VRM の小窓・VOICEVOX・通話・声かけ |
| `web` | 207 | 家庭用 Web アプリ。API・認証（passcode）・画面の器 |
| `integration` | 193 | 外部連携——Slack・Notion・カレンダー（ICS） |
| `guard` | 182 | **規約の番人**。製品の振る舞いではなく「書き方」を見張る |
| `staff` | 177 | 担当——料理長・家政婦・秘書・家令 |
| `night` | 118 | 無人実行——夜勤・関門 |
| `platform` | 107 | 環境まわり——Windows・登録・拡張 |
| `board` | 71 | ダッシュボード |
| `migration` | 61 | v1 からの移行 |

合計 1,768（収集時。`-m` で足すとちょうどこの数になる＝漏れも重複も無い）。

## `guard` が何をしているか

ここだけ毛色が違う。**製品が正しく動くか**ではなく、**執事が規約どおりに書いているか**を見る。

- `test_i18n_no_hardcoded_japanese`（112件・最大のファイル）——画面に出る文字列を
  コードに直書きしていないか。許可リストは行番号で持つので、行がずれると鳴る
- `test_privacy_boundary`——②④（主人の情報・環境固有）が外へ出る経路に入っていないか
- `test_staff_isolation`——担当が自分の表以外に書いていないか
- `test_night_entrypoints_agree`——夜勤の起動口が2つあり、食い違っていないか（G15）
- `test_frontend_parity`——画面と API の型が合っているか

## カテゴリの表は列挙式

`TEST_CATEGORIES` は上から照合する列挙で、**完全性に全部を頼っている**（B174 で学んだ形）。
そのため `tests/test_categories.py` が見張る:

- 表に当たらない試験ファイルが1つでもあれば落ちる
- 印が `pyproject.toml` に説明つきで登録されていなければ落ちる（未登録は警告止まりで
  流れてしまうため）
- 中身が1つも無いカテゴリがあれば落ちる（`-m` で回した人に「試験が無い」を
  「通った」と読ませない）

⚠ 受け皿は `"tests/test_"`（**直下のみ**）。`"tests/"` にすると何でも拾って
`category_for` が `None` を返さなくなり、**見張りが空回りする**（2026-09-07 に一度そう
書いて気づいた）。新しい下位ディレクトリは必ず表に足すこと。
