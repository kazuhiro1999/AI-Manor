# archive — 追記ファイルに寿命を持たせる

外部レビューへの応答（`docs/design/ADR-006_external_review_2026-09.md` §4）。`CHANGELOG.md` ／
`butler/GROWTH.md` ／ `home/LOG.md` はどれも**追記のみ**で育つファイルで、放っておくと
際限なく太る。`manor check` の C10（40KB 超で警告）が育ちすぎを教え、`manor archive` が
古い月を別ファイルへ**移す**（消さない）。

## 使い方

```
uv run python -m manor.archive <path> [--keep-months 1] [--dry-run] [--json]
```

`manor archive ...`（`cli.py` への配線）は本モジュールの担当範囲外。`archive.py` は
`register(subparsers)` を公開しているので、配線自体は他のプラグインと同じ1行で足りる。

- `<path>`: `CHANGELOG.md` ／ `butler/GROWTH.md` ／ `home/LOG.md` などの追記ファイル
- `--keep-months`（既定1）: 直近この月数ぶんは元ファイルに残す。それより古い月を移す
  （「今日」は `MANOR_TODAY` があればそれ、無ければ実時刻。**時計は必ず固定して試験する**
  ——`butler/GROWTH.md` G1 の教訓と同じ）
- `--dry-run`: 何を移すかだけ表示する。書き込みは一切しない
- `--json`: 結果を JSON で出す

## 3つの書式（中身の形で自動判定する。ファイル名では決め打たない）

| ファイル | 書式 | 月の切れ目 |
|---|---|---|
| `CHANGELOG.md` | 見出し | `## YYYY-MM-DD` の行（`###` のサブ見出しは巻き込む） |
| `butler/GROWTH.md` | 表の行 | `| G1 | YYYY-MM-DD | ... |` のような、どこかのセルが日付になっている行 |
| `home/LOG.md` | 箇条書き | `- YYYY-MM-DD ...` の行（続く字下げ行も同じ塊として移る） |

どの形にも当たらなければ「対象外」と言って何もしない（エラーにしない）。日付の無い前置き
（タイトル・凡例の表など）はどの書式でも動かさず、元の位置に残る。

## 移し先

- `CHANGELOG.md` 相当（`LOG.md` 以外）: `<path> から祖先方向に辿って最初に見つかる
  `docs/` を持つフォルダ>/docs/archive/<拡張子を除いたファイル名>-<YYYY-MM>.md`
  （見つからなければ `<path> の親>/docs/archive/...`）
- `home/LOG.md`: `<path の親>/archive/LOG-<YYYY-MM>.md`（実運用では `home/archive/`）

月ごとに1ファイル（`CHANGELOG-2026-07.md` と `CHANGELOG-2026-08.md` は別ファイル）。

元ファイルには、移した月ごとに1行の索引を残す:

```
<!-- archived: 2026-07 → docs/archive/CHANGELOG-2026-07.md（3件） -->
```

## 消さない・冪等・追記（ADR-006 D19）

- 元ファイルの内容を消すのではなく**移す**（宛先ファイルに書いた上で、元からは索引コメント
  に差し替える）
- 2回目に同じ `<path>` に対して回しても、移す月が残っていなければ何もしない
  （宛先ファイルに触らない）
- **宛先ファイルが既にあれば上書きせず追記する。** 「アーカイブ→（夜勤の前日報告・抜けた
  LOG の補完などで）その月の日付を持つエントリを遡って追記→再アーカイブ」という運用は
  普通にある。以前は宛先が既にあると書き込み自体をスキップしていたため、遡って足した
  エントリが元ファイルからは消えるのに宛先にも残らず**消失**していた（②の `home/LOG.md`
  は git で戻せないため最悪の型）。いまは宛先を必ず追記で保存する
- 索引行の件数（`（N件）`）は「今回移した件数」ではなく、**宛先を書いたあとに読み直して
  数えた累計件数**（`_parse_blocks` で宛先を再び分割し、`entry` ブロックを数える）
- 元ファイルに同じ月の索引行が既にあれば、新しい行で**その場を置き換える**（索引行を
  2本にしない）。索引行がまだ無ければ、これまでどおりその月の最初のエントリがあった
  位置に置く。索引行は見出し・箇条書きの「地の文（keep）」の中に埋もれて残るため、
  行単位まで割ってからでないと正しく見分けられない
- **書く順序**: ① 移し先を（月ごとに）全部書く（無ければ作る。ディレクトリを作り、
  追記モードで開いて書いて flush する）→ ② 全部成功してから宛先を読み直して累計件数を
  確定する → ③ 元ファイルは直接上書きせず、同じディレクトリの一時ファイルに書いてから
  `os.replace` で入れ替える。**移し先の書き込みが1つでも失敗したら、元ファイルにはまだ
  一切触れていないので何も変わらない**（例外はそのまま呼び出し元へ伝播する）
- 追記の直前に移し先の末尾を見て、既にあって空でなく末尾が改行で終わっていなければ先に
  改行を1つ書く。追記する内容自体が改行で終わっていない（元ファイルの最終行に改行が
  無かった）場合も同様に補う。これを怠ると `open(..., "ab")` がそのまま連結し、2件が
  1行に融合して `_parse_blocks` の件数まで狂う

## 表形式のヘッダを複製する（ADR-006 D20）

`butler/GROWTH.md` のような表形式（`fmt == "table"`）は、移した行だけを書き出すと
Markdown の表として描画できない。**宛先ファイルを新規に作るときだけ**、元ファイルで
最初のエントリ行の直前にある `|` 始まりの連続行（典型的にはヘッダ行と区切り行の2行）を
先頭に複製する。**追記のとき（宛先が既にある）は複製しない**（ヘッダが増殖しない）。
見出し・箇条書きの形式では何も複製しない（そもそもヘッダ行という概念が無い）。

## `manor check` C10 との関係

`manor check` の C10 は `CHANGELOG.md` ／ `butler/GROWTH.md` ／ `home/LOG.md` が40KBを
超えたら警告する（赤にしない。`manor check` 全体の終了コードには影響しない）。
`/brief week` の「規則の棚卸し」がこれを見て `manor archive` を促す（ADR-006 §4 D15）。

## 曖昧だった点

- **`--keep-months` の基準は「今日」（`util.today()`。`MANOR_TODAY` で固定可能）からの
  相対月**であり、「ファイル内で一番新しい月」ではない。ADR の文面（「指定より古い月を
  移す」）はどちらの読み方もできたが、`util.today()` が `MANOR_NOW`/`MANOR_TODAY` による
  固定に対応済み（既存の設計と揃える）という理由でこちらを選んだ。試験は日付を固定して
  書いている
- **移し先の `docs/` 探索は最大3階層まで祖先を遡る。** 見つからなければ `<path> の親>/docs/archive/`
  にフォールバックする（合成データを使う試験がリポジトリの外で完結できるようにするため。
  本物のリポジトリでは `CLAUDE.md`・`butler/GROWTH.md` のどちらから見ても2階層以内に
  `docs/` が見つかるので実害は無い）
- 一時ファイルの名前は `<path の名前>.tmp` の固定名（`os.replace` の直前だけ存在する）。
  同じ元ファイルに対して `apply()` を並行に走らせる運用は想定していない（`manor archive`
  は対話的・単発の起動が前提）
