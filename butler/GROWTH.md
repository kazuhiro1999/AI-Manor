## G14 — 「やりました」の前に、返り値を見る（2026-09-06）

**観測**: v1 から v2 へ切り替える日、`manor night install --at 02:00 --yes` が
「登録しました」と言った。実際には schtasks が終了コード 2147500037 で落ちていて、
**タスクは1本も登録されていなかった**。気づいたのは、たまたま `Get-ScheduledTask` で
確かめたからで、確かめなければ**今夜の夜勤が動かない**まま朝を迎えていた。

**なぜ起きたか**: `install()` は `subprocess.run` の結果を辞書へ詰めていたが、
`returncode` を**誰も読んでいなかった**。CLI は `result["executed"]`——「実行を試みたか」
——だけを見て「登録しました」と表示し、終了コード0を返していた。**試したことと、
できたことを、同じ言葉で言っていた。**

**打ち手**: `install` / `uninstall` の結果に `ok`（真偽）を持たせ、CLI は失敗なら理由と
終了コード1で止まる。あわせて `/TR` の中の `"` を逃がした（落ちていた直接の原因は、
リポジトリのパスに空白があること）。

**一般化**: これは夜勤に限らない。**外の何か（OS・API・別プロセス）に頼んだ仕事は、
頼んだことと済んだことが別。** 執事が「送りました」「登録しました」「消しました」と
言えるのは、**返り値か、外から見た実物か、どちらかを確かめたときだけ**。
今回は `Get-ScheduledTask` で実物も見た——両方見るのが一番強い。

**残る限界**: 同じ形が `manor shortcut create` や `manor web install` にも在りうる。
今回は数えていない（数えるべきだが、切り替えの当日に手を広げないことを選んだ）。

## G15 — 起動口が2つあるものは、片方だけが使われている（2026-09-06）

**観測**: `--sleep-back` を `manor night` 側に足し、試験も19件書いて全部緑にした。
そのあと**登録したコマンドをそのまま手で叩いてみたら**、`python -m manor.night run
--sleep-back` が `unrecognized arguments` で落ちた。夜勤の起動口は2つあり、
**スケジューラに登録されているのは試験していないほう**だった。叩いてみなければ、
翌朝「夜勤が丸ごと動かなかった」で気づくことになっていた。

**なぜ起きたか**: `__main__.py` が引数の定義を**書き写していた**。しかもその docstring
には「同じ dest 名を使い、二重に書いて食い違わせない」と**書いてあった**——
散文で「食い違わせない」と誓っても、食い違いは防げない。v1 README が
「機構は散文では守られない」と言っていたのと同じ形を、自分でもう一度踏んだ。

**打ち手**: `__main__.py` は `_add_*()` を呼ぶだけにした。`notion.py` も同じ形
（`register()` と `main()` の書き写し）だったので、共通の組み立てに寄せた。
そのうえで**2つの口が同じ引数を受けることを試験にした**
（`tests/test_night_entrypoints_agree.py`）——書き写しが戻ってきたらそこで落ちる。

**一般化**: **同じ機能に入口が2つあったら、片方は必ず腐る。** 腐るのは、使われて
いないほうではなく**試験されていないほう**で、その2つはたいてい一致しない。
今回は「実運用が叩くほうが、試験の無いほう」という最悪の組み合わせだった。
入口が2つある機能を触ったら、**登録・配線されている側から叩いて確かめる。**

⚠ **試験の側で引数を書き写さないこと。** それをすると「試験と実装が一致している」
ことしか言えず、肝心の「2つの入口が一致していること」は何も言えない。今回いちど
その形の試験を書きかけて、気づいて捨てた。

**残る限界**: `manor slack` / `manor notion` は今回そろえたが、`board` にも同じ
2つ口の形がある（`register()` と `__main__.py`）。数えていない。
