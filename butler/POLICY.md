# POLICY.md — 権限ポリシー（policy-as-code）

> 「都度の目視確認」を「宣言されたゲート」に置き換えるための宣言書。
> **行動クラスの既定レベル・プリセットの7軸展開・合成規則の表は `butler/policy.toml` が正本です。**
> ここには表を複製しません（同じ表が2箇所にあれば必ずずれます）。値を引くときは
> `manor policy resolve <class> [--project code]` を使います。
> ナレッジ層（本ファイル）＋機構層（DB の状態機械・`.claude/settings.json`）の2層で運用します。

## 自律レベル

| L | 名前 | 執事の動き |
|---|------|-----------|
| L0 | 観測 | 読む・調べる・要約する。報告のみ |
| L1 | 提案 | 案を作って提示。実行はしない（`manor decision ask` へ積む） |
| L2 | 自律実行＋事後報告 | 聞かずにやる。DB に記録し、会話で1行報告 |
| L3 | 自律実行＋記録のみ | 報告も省略。ログにだけ残す |
| HG | human_gate | 主人の明示承認が必須。**待たずに `manor decision ask` へ積んで次の作業へ** |

## プリセットの意味

プロジェクトごとに `careful`（🐢慎重）/ `standard`（🚶標準）/ `fast`（🏃高速）のいずれかを持ちます。
同じ依頼でも、厳密さが要る案件は 🐢 で確認を厚く、方針が固まっていない案件は 🏃 で
主人の設定が要るときだけ止まります。**`autonomy` は `risk` と独立に決めます**
（「実務＝常に慎重」のように固定しない。決めるべきは risk に対して適切な autonomy です）。
7軸（autonomy / risk / verification / approval / scope / research_freedom / escalation）の
具体値と、プリセットが既定レベルを何段ずらすかは `butler/policy.toml` [axes] [presets] を参照します。
**ただし HG は決して上げません。** 不可逆・外部送信・認証・課金・個人情報はどのプリセットでも
human_gate のままです（`policy.toml` の `fixed = true`）。

## 「質問する」か「進める」かの判断

聞くこと自体を目的にしない。**確認コストと誤判断コストを比べます。**

| 進めてよい | 質問する |
|---|---|
| risk が低い／可逆／テストで検証できる | risk が高い／**不可逆** |
| 仮説を置いても容易に直せる | 仕様上の選択で結果が大きく変わる |
| 主人の目的が十分に明確 | 業務上の暗黙知が要る |
| 確認コスト > 実装コスト | 誤判断の修正コストが高い／プリセットが 🐢 慎重 |

## 迷ったときの規則

1. **可逆なら進む。不可逆なら積む。** 判断軸は「間違えても5分で戻せるか」
2. リスク判定に迷ったら**1段階上げる**
3. 「主人に聞けば早い」は理由にならない。聞くコストは主人の時間、進めるコストは執事のやり直しだけ
4. 同じ判断を2回聞いたら、それはポリシーに書くべき事項。次から `policy.toml` に書いて自律化する

## 成果物メタデータ（HG / L1 のとき必ず添える）

```
risk:           low | medium | high
reversibility:  easy | moderate | hard
impact:         影響が及ぶ範囲
evidence:       根拠（実行ログ・参照ファイル・出典）
```

**根拠のない報告は無効**。「たぶん大丈夫」は evidence になりません。

## 新しい配線を足すときの判定器

上の表は「執事の行動をどこまで許すか」を測ります。**もう1つ、「配線そのものが危ないか」を
測る表**を持ちます。用途が違うので、両方引きます。

**3つが1つの経路に揃うと、プロンプトインジェクションで抜かれます**（*lethal trifecta*）:
**①非公開データへのアクセス ＋ ②信頼できないテキストへの曝露 ＋ ③外部への送信能力**。
**揃わないように配線するしか守る手はありません。** 検出で守ろうとしても、この分野の
「95%ブロック」は落第点です（残り5%を突かれれば同じこと）。

| 経路 | ①非公開データ | ②外部テキスト | ③外部送信 | いま |
|---|:---:|:---:|:---:|---|
| | | | | |

<!-- 新しい配線（コネクタ・チャンネル・自動化・道具の追加）を足すたびに、この表に1行足す。
     3つ揃うなら、足す前にどれか1つを落とす。 -->

**規則**:

1. **新しい配線を足すたびに、この表に1行足す。** 3つ揃うなら、**足す前にどれか1つを落とす**。
   **表の「いま」に書くのは、機構で塞いだものだけ。** 命じてあることは、塞いであることではない
2. **道具は経路ごとに絞る。** ワークスペース全体ではなく、**呼び出しの許可リスト**に書く
3. 主人以外がその経路に入る日が来たら、その日が②の前提を見直す日

## Git 運用の線引き

**既定ブランチへの直接 `push` と Pull Request の**マージ**は HG（固定・執事は緩められない）。**
ローカルの `add`/`commit`、作業ブランチの作成・`push`、PR の作成は L2（聞かずに進めてよい）。
`push --force` / ブランチ削除 / 履歴書き換えは HG（固定）。リモート追加（`git remote add`）は
機構層（`.claude/settings.json` の deny）で止めてあります。

## 本ポリシーの改訂

執事が改訂してよい（L2）。ただし **HG固定行（認証・課金・個人情報・外部送信・不可逆削除）は
執事が緩められない**。緩和したい場合は `manor decision ask` に提案として積む。
改訂したら `butler/GROWTH.md` にも1行残す。
